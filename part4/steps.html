Module 4 · Coded Agent

Build the Claims Settlement Agent

Learn what a Coded Agent is, then scaffold, write, test, package, publish, and run the Claims Settlement Agent — a pure-Python agent with no LLM.

Concepts

What's a Coded Agent?

A Coded Agent is agent logic written entirely in Python. You author its states and tool calls directly in code; the UiPath SDK provides the platform layer underneath — packaging, publishing, governance, and observability. You can optionally bring in a framework extension like LangChain or LlamaIndex for LLM-driven reasoning, or skip an LLM entirely and write fully deterministic business logic, as you will in this module.

Why Coded Agents?

A surge in domain-specific AI agents is driving demand for custom, code-based solutions. Professional developers want to be the architects of these systems, and enterprises want more than raw automation speed — they want auditability and control.

🧑‍💻

Professional developers

Design, test, and scale complex multi-agent workflows with full control.

📈

Agentic growth

Rapid adoption of AI agents fuels demand for customized, domain-specific solutions.

🛡️

Enterprise requirements

Auditability, traceability, and guardrails — not just automation speed.

Coded Agents let developers package, publish, and deploy Python-authored agents under the same governance as every other UiPath automation.

🔗

🌐

🏛️

Enterprise guardrails

Pack, publish & deploy with RBAC, audit logs, stateful memory & HITL interrupt nodes.

The mental model

Think of a coded agent as a graph: nodes are actions, edges are transitions between them. UiPath discovers your agent from a small, well-defined contract in your code — you don't need to describe the graph by hand.

ConceptIn LangChain / LlamaIndex termsIn your code
NodeA state — an action or tool callA Python function (optionally @traced)
EdgeA transition based on a result or conditionControl flow (if, calls) inside main()
ContractGraph entry pointsInput / Output models + main()
Memory / HITLCheckpoints & interrupt nodesSDK memory stores & Action Center
ℹ️ An LLM is optional
The Settlement Agent you build later in this module is pure deterministic logic — no model calls. Coded agents are just as useful for auditable business rules as they are for LLM reasoning.

How it works

A coded agent moves through five stages, from definition to observation:

Key features

SDK components

  • Graph-based orchestration (states, edges, transitions)
  • Memory stores & checkpoints for statefulness
  • Interrupt nodes for human-in-the-loop flows
  • Native use of the UiPath LLM Gateway & Studio evals

Orchestrator & integration

  • Invoke UiPath processes; be invoked by any trigger
  • Feeds, versioning, solutions, Action Center checkpoints
  • Established package → process → job lifecycle
  • CLI pack & publish straight from your local IDE

Monitoring

  • Real-time logs, traces, drift detection, cost alerts
  • Orchestrator job monitoring & instance management
  • AI Trust Layer governs every LLM call

Controlled agency

Guardrails are layered across every level — the AI Trust Layer (model policies, PII filters, audit logs), automation-ops policies for all agents, and per-agent tool guardrails & memory/traces. The result: autonomy within clear, compliant boundaries.

The build & publish lifecycle

Six CLI commands take you from an empty folder to a governed cloud job. This is exactly what the hands-on section below walks through.

Build the Agent

You'll build a no-LLM coded agent that settles an insurance claim: given an insurance type, coverage type, and claim amount, it returns the settled amount using simple business rules. All commands below are run from Windows PowerShell — you'll edit files with Notepad, never by typing code directly at the PS> prompt.

The business rules

Eligible insurance types

Matched if the name contains (case-insensitive):

  • Medical
  • Stole
  • Theft
  • Water Damage
  • Vehicle
  • Fire

Settlement percentage

  • Full coverage → settle 95% of claim
  • Partial coverage → settle 90% of claim
  • Any other type or coverage → not eligible, settle 0

Decision at a glance

Insurance type contains…CoverageResult
Medical / Stole / Theft / Water Damage / Vehicle / FireFull95% settled
Medical / Stole / Theft / Water Damage / Vehicle / FirePartial90% settled
Anything else—Not eligible (0)
Eligible typeNeither Full nor PartialNot eligible (0)
🏷️ Inputs & outputs at a glance
Inputs — insurance_type (string), coverage_type (string), claim_amount (float)
Outputs — eligible (boolean), settlement_percentage (float), settlement_amount (float), message (string)

3

Write main.py

Open main.py in Notepad, select all and delete the generated starter content, then paste the code below. Every coded agent needs an Input model, an Output model, and a main function — this one uses Pydantic and @traced, with no LLM imported.

PowerShell
PS> notepad main.py

In Notepad: press Ctrl+A, delete the existing content, paste the code below, press Ctrl+S to save, and close Notepad.

main.py
from pydantic import BaseModel, Field
from uipath.tracing import traced

ELIGIBLE = ("medical", "stole", "theft",
            "water damage", "vehicle", "fire")
RATES = {"full": 0.95, "partial": 0.90}

class SettlementInput(BaseModel):
    insurance_type: str = Field(..., description="e.g. 'Vehicle'")
    coverage_type: str = Field(..., description="'Full' or 'Partial'")
    claim_amount: float = Field(..., ge=0)

class SettlementOutput(BaseModel):
    eligible: bool
    settlement_percentage: float
    settlement_amount: float
    message: str

@traced(name="match_insurance_type", run_type="uipath")
def _match(t: str):
    t = (t or "").strip().lower()
    return next((c for c in ELIGIBLE if c in t), None)

def main(input: SettlementInput) -> SettlementOutput:
    category = _match(input.insurance_type)
    rate = RATES.get(input.coverage_type.strip().lower())

    if category is None or rate is None:
        return SettlementOutput(
            eligible=False,
            settlement_percentage=0,
            settlement_amount=0,
            message="Not eligible"
        )

    amount = round(input.claim_amount * rate, 2)

    return SettlementOutput(
        eligible=True,
        settlement_percentage=rate * 100,
        settlement_amount=amount,
        message=f"Settled at {rate * 100:.0f}%"
    )
ℹ️ Required structure
Two Pydantic models (Input, Output) and one entry function named main, run, or execute. That is all UiPath needs to discover your agent.
4

Configure uipath.json and pyproject.toml

Open uipath.json in Notepad and replace its content — the functions map names the coded-agent entrypoint as Claims_SettlementAgent.

PowerShell
PS> notepad uipath.json
uipath.json
{
  "functions": {
    "Claims_SettlementAgent": "main.py:main"
  }
}

Then open pyproject.toml in Notepad and replace its content — this declares your project metadata and dependencies. Only uipath is required; no LLM framework is needed.

PowerShell
PS> notepad pyproject.toml
pyproject.toml
[project]
name = "Your_Name_Claims_SettlementAgent"
version = "0.0.1"
description = "Insurance claims settlement agent"
authors = [{ name = "Your Name" }]
dependencies = ["uipath>=2.10.0, <2.11.0"]
requires-python = ">=3.11"
📝 Note
Replace Your_Name_Claims_SettlementAgent and Your Name with your actual project name and your name — matching the folder you created in step 1.
5

Remove langgraph.json

The codedagent new template generates a langgraph.json file, but this project uses the UiPath coded-agent entrypoint defined in uipath.json instead. Delete it before initializing the project.

PowerShell
PS> Remove-Item langgraph.json
⚠️ Don't skip this step
Keeping langgraph.json causes initialization to look for a graph object in main.py and produces a "graph not found" error. Always remove it before running codedagent init for this style of no-LLM coded agent.

Publish & Run

Package, log in, publish to Orchestrator, and invoke a governed cloud job — the four steps that take your tested agent to production.

9

PowerShell
PS> uip codedagent pack
✓ Package created successfully.
📝 Note
Confirm the package is created successfully before continuing to the next step.

Log in to UiPath

Publish the coded agent

12

Invoke the published agent

Run the published agent in the cloud with codedagent invoke, passing the same input.json file with -f.

PowerShell
PS> uip codedagent invoke Claims_SettlementAgent -f input.json
⯈ Job started in Orchestrator.

output
├── eligible: True
├── settlement_percentage: 95.0
├── settlement_amount: 9500.0
└── message: Settled at 95%

✓ Successful execution.
⚠️ Use the JSON file, not inline JSON
Always invoke with -f input.json. The inline JSON form (passing the object directly on the command line) was tested and failed validation in this environment.

Because it is now an Orchestrator package, the agent inherits RBAC, audit logs, job monitoring, versioning, and one-click rollback — and it can be invoked by any trigger or UiPath process.
